# Atlas workspace, connected notes, AI and sync

18 November 2026. This is the review plan for the next Atlas work. It records the feedback and proposed defaults. Implementation starts after approval.

Atlas should feel like a compact asset browser when you are sorting files and like a connected workspace when you are writing or exploring a project. Use the Eagle references to guide density, hierarchy, preview behavior and menu placement. Use the Obsidian reference for graph interaction and tabs. Atlas keeps its own visual identity in both light and dark themes.

The [reference index](references/INDEX.md) describes the 20 screenshots in the feedback, in order, and links to the available earlier Eagle recording frames. No repository changes are part of this planning pass.

## 1. Fix saving and everyday interaction

- **Autosave all item edits.** Save title, notes or description, URL, tags, folder membership, rating, links, Markdown and related fields. Clicking a rating or adding a tag can save immediately. Typing saves after a brief pause. Save pending changes when switching items or tabs. Keep a recoverable local draft if a write fails or the app closes abruptly. If another device or agent changed the same field, show both versions and preserve the user's work. Remove **Save changes** from the inspector once this passes testing. Use a small saving or error status where useful.
- **Deselect cleanly.** Clicking empty gallery space, pressing Escape or clearing a graph selection clears item details. Proposed default is to collapse the inspector on an empty Home selection and show folder-level details when browsing a folder. If both panels are collapsed, `Ctrl+/` restores their prior visibility. Start with narrower sidebar and inspector widths. Allow resizing and remember the settings.
- **Work with the keyboard and mouse.** Arrow keys move focus across the gallery by the actual rows and columns. In List, Up and Down move row by row. Keep focus visible and scroll it into view. Enter opens the focused item. Use Shift+click for a range, Cmd/Ctrl+click or checkboxes for individual toggles, and drag a rectangle from empty gallery space to select. Support Cmd/Ctrl+A, copy, paste, context-click, and platform-appropriate Delete shortcuts. `Shift+F10` or the context-menu key opens actions for the focused item. Delete moves items to Trash and can be undone. Standard text editing shortcuts keep working in fields and notes.
- **Restore preview reliability.** Hovering or keyboard-focusing the magnifier on a Markdown item shows a rendered excerpt. Create and cache a representative video frame in the background on import or when an older video is first seen. Reuse the thumbnail on reopen and keep hover-to-seek. Show a clear fallback when a codec cannot be decoded. Use a subtle 1–2% zoom on static thumbnails and reduce motion when the system requests it. For video, keep the tile steady and use the poster-to-seek transition as the hover response. Draw the focused or selected border around the media and change the caption color separately.

**Check before release.** Edit a note and its metadata, switch items and restart the app without losing a change. Test two edits to the same item, hardware and trackpad keyboard actions, Markdown previews, and thumbnail generation or fallback for real video samples on Mac and Windows.

## 2. Make browsing simpler

- **Home and search.** Use one aligned search field with an **All types** selector built into it. Fix the nested field and width alignment. Keep a single result count close to the results. Show **Grid** and **List** as the primary views, with tooltips, shortcut hints and accessible names that work on keyboard focus. Keep Graph available as its own workspace. Place other existing gallery layouts and specialized views in the View menu. Move selection actions into menus or a small contextual toolbar. Remove the permanent Select All button, per-tile ellipses and the separate Quick Preview call to action. Keep the magnifier for previews. Use a general **New** dropdown with Markdown first and room for more formats. Keep **Import files** as a separate action.
- **Filters.** Put advanced filters in one compact control beside the search field. Make active filters visible and removable. The type selector should list actual library file extensions and counts with checkboxes and an include/exclude action. Provide the same keyboard access as the mouse. Tags and Folders get searchable lists with checkboxes, counts, include/exclude and match options where they make sense. Keep Shape and Rating accessible. Share type state between the search selector and advanced filters.
- **Color.** Trace the reported hex mismatch before assigning a root cause. Normalize `#RGB`, `#RRGGBB`, case and optional leading `#` for pasted values. Store one normalized palette format for native imports and mapped Eagle colors. Put palettes for older items into a background indexing queue so results do not depend on which images have been scrolled into view. Offer a picker, preset swatches, pasted hex and a similar-color tolerance. On hover or focus show the hex and coverage when measured. Provide a swatch menu for Find similar colors, Copy in HEX, RGB/RGBA, HSL, HSV, HWB or CMYK, and Set as primary color. Use the same color in the inspector and the filter.
- **Sidebar and folders.** Use shorter rows, disclosure triangles and tree guide lines. Keep a small folder filter. Move Eagle folder repair and other occasional utilities into Library or Help. Remove permanent row-level hover controls for rename and add subfolder. Offer folder commands on right-click or via the keyboard. A parent folder shows subfolder tiles first and a Contents area underneath. By default show files directly in the current folder. **Show subfolder contents** adds descendant items once each while keeping the folder tiles visible. Empty subfolders stay visible. Include folder deletion with a preview of affected branches and memberships. Proposed deletion keeps the files in the library. Files with no remaining folder membership go to Uncategorized. Support Undo for the folder tree and its memberships.
- **Two kinds of zoom.** For the Home gallery, keep a thin thumbnail size track, a handle that expands on hover/focus and small minus/plus buttons. A trackpad pinch steps through thumbnail sizes one level at a time. For an individual image, a plain click opens an in-place detail view that takes over the center. Keep the sidebar and inspector at their current widths. Transition the center toolbar in place, with a compact group for zoom out, percentage or slider, zoom in, Actual Size and Fit to View. Try the controls at the bottom of the detail canvas with Back and context at the top. Smoothly zoom around the pointer or gesture center and support pinch and pan. Navigate images with arrow keys and return with Escape or Back. Keep separate next/previous buttons off the toolbar.
- **Inspector and exports.** Use the screenshots for the order and proportions of the preview, swatches, editable title and notes, source link, tags, folders, rating, dimensions, size, type and dates. Keep chips and their add/remove controls compact. Put export in one contextual menu. Include existing exports for originals and Markdown, plan CSV for visible item metadata, and add an image format and dimension export. An Atlas package would group selected files with their metadata. Eagle `.eaglepack` export compatibility needs its own decision and verification. Keep Atlas links, revisions and MCP-related capabilities available through appropriate submenus or workspace sections.
- **Menus and customization.** Group supported commands under **Library, File, Edit, Find, Organize, View, Window and Help**. Keep agent setup discoverable in a dedicated Agents menu or submenu. File covers New/Markdown, folders and smart folders, import and export. Edit covers clipboard, undo/redo, rename, duplicate and thumbnail actions. Find covers search, sidebar filtering, similar-color and image search, and Go to Folder. Organize covers tags, folder membership, rating, and Trash. View covers layout, sort, panels, thumbnails, zoom, grayscale, optional names and info, subfolder contents and presentation. Help covers shortcuts, updates, and diagnostics. The reference index captures the additional menu examples. Expose commands when supported. Use contextual menus and checkboxes for the most common actions and make the same commands available from the keyboard.

**Check before release.** Compare Home, folder, detail and inspector states in both themes. Try a folder with nested and empty children, a filter combination, keyboard-only selection and navigation, and zoom on a trackpad. Check the toolbar at narrow window widths.

## 3. Make writing and linking part of the same workspace

- **More editing space.** Give Markdown more of the center pane with a comfortable adjustable reading width. Use live formatting so headings, lists, code and inline styles are recognizable when the cursor moves off them. Keep Markdown round-tripping as the saved format. Prototype CodeMirror 6 decorations for inactive lines and range-anchored popovers. Test pasted content, composing text, undo, large notes and existing Atlas links. [CodeMirror decorations](https://codemirror.net/examples/decoration/)
- **Slash menu and link picker.** Position the slash menu beside or below the caret, flipping it above near the bottom of the viewport. Keep the caret visible. Add `/link`, `/embed` and a connection command such as `/connect` for labelled relationships. Open the same searchable picker from the plus icon. The search and results stay anchored in the current editor view. Search by title and type and sort by date or type. Show an item preview on hover and keyboard focus. Support checkboxes to attach several items, keyboard navigation, Escape to return focus, and insertion at the original caret position.
- **Inline image imports.** Paste, drop or choose pictures in the editor. Create a separate library asset for every imported image and insert its inline embed. The link should still work after a rename or folder move. Show upload progress and only insert a working embed once the asset is saved. Proposed default is to inherit the note's tags and keep the asset in Uncategorized until an explicit routing rule matches. Offer rules that map selected note tags to designated folders.
- **Tabs and split panes.** Allow notes, images, library results and graph views to open in independent tabs. Remember each tab's caret, selection, scroll, pan and zoom. Add an optional two-pane split for pairs such as a note and its connections. Reuse one editing state per item even if it is open in two places. Start with tabs before adding the split.

**Check before release.** Open the slash menu near the bottom of a long note, create a heading, add two existing links and paste two new images. Switch tabs and return to the same caret. Follow a link before and after the target is renamed. Confirm the pasted images exist as library items and render in the note.

## 4. Improve the connected graph

Atlas already uses open-source Cytoscape.js. The current view takes the first 250 items and creates a new graph when its inputs change. Start by keeping a single graph alive and updating only changed nodes and links. Preserve the camera and positions when a note autosaves, a filter changes or a different node gets selected. Add a quick local graph centered on one item and a searchable library-wide graph. Bring in relationships by stable ID, including typed relations, links, embeds and backlinks. Provide filters for tags, media and notes, relationship type and disconnected items, with a compact control for layout and display. Focus or hover highlights connected neighbors, with a quick path to open the item in a tab. Limit labels at small zoom levels and provide a keyboard-accessible connection list. [Cytoscape.js](https://js.cytoscape.org/)

Benchmark incremental Cytoscape updates first, with representative small and larger libraries. Keep pan and zoom responsive while layout work happens separately. If rendering still slows down at the target scale, test the open-source Sigma.js and Graphology combination. Sigma uses graphics hardware for drawing and Graphology provides graph data and layout utilities. Keep Atlas's item and relationship model independent of the rendering choice. [Sigma.js](https://www.sigmajs.org/) · [Graphology](https://graphology.github.io/)

**Check before release.** Open the graph for a real note, add a link, and verify the connection appears without snapping the camera or dropping keyboard focus. Compare responsiveness using small, medium and large fixtures. Record performance and use it to choose the renderer.

## 5. Add native AI writing and library management

An AI model generates the writing or proposes changes. MCP is the standard connection that lets a compatible external assistant ask Atlas to find an item, read a note or submit a proposed change. Atlas's API is how the app itself sends a request and records the result. Both routes should use the same library rules and revision history. Atlas already has local tag and description suggestions through Ollama and optional local MCP editing tools. [MCP overview](https://modelcontextprotocol.io/docs/learn/architecture) · [Ollama structured output](https://docs.ollama.com/capabilities/structured-outputs)

| Route | What you would use it for | Cost and tradeoff |
|---|---|---|
| Native Atlas AI with a local model | Continue, rewrite, summarize or outline a note. Tag, categorize and describe images or supported files, one at a time or in the background. | Runs on a computer you already own with a compatible local model. No per-request provider charge. Model performance depends on the machine. |
| Atlas MCP for compatible assistants | Ask Codex or another MCP app to find project material, draft from it, suggest related items or submit a batch proposal. | Atlas controls which tools and data the assistant can use. The assistant's own plan governs its costs. A hosted client needs a supported private connection or authenticated remote service. |
| Optional hosted AI API | Use a model from a provider through the same Atlas controls for writing or image understanding. | It may charge for usage and receives the content selected for processing. Make it opt-in and show the selected provider, scope and applicable limits. |

Start with native local writing and a batch proposal queue for tags, descriptions, folders and relations. Let users review changes together, see what happened and undo them. Allow explicit per-library rules to auto-apply low-impact additions such as approved tags or folder memberships. Require review for rewriting existing text, moving groups of files, or destructive changes. Use saved tags and folder names as preferred vocabulary. Capture changes with revision history. Keep read access as the default when setting up MCP and offer scoped proposal tools for external assistants. Hosted ChatGPT connectivity is a separate integration with its own supported connection and authorization. [OpenAI custom MCP guide](https://developers.openai.com/api/docs/guides/custom-mcp-server)

## 6. Store locally and add sync in stages

Your Atlas library stays in a dedicated folder on each device. Think of it as a catalog alongside the originals. The catalog stores notes, tags, folders, links and edit history. Atlas stores identical file bytes once per library. A backup is a recoverable copy at a particular time. Sync keeps devices up to date as you work. Atlas can build both on the same portable library format.

| Option | What it feels like | Cost and tradeoff |
|---|---|---|
| Verified backups | Export a dated library copy and restore it on a different Mac, Windows PC or Android phone. Store the finished copy on a disk or in an existing cloud drive. | Zero new service cost with storage you already have. A manual transfer still requires a copy. Keep the live Atlas catalog on the device and place completed archives in shared drives. |
| Atlas device pairing on Wi-Fi | Pair two devices with a one-time code. Open Atlas on both, and changes move between them over your local network. Android can start with sync while the app is open. | Zero required hosting spend using your existing network. Devices need to be online together. This is the first automatic-sync option I recommend for personal use. |
| Hosted accounts and sync | Sign in on each device and catch up when it goes online, even when the original laptop is closed. | Supabase is a candidate for logins and the catalog. Its free tier lists 500 MB database space and 1 GB file storage with a 50 MB per-upload ceiling, so treat it as a small pilot. Cloudflare R2 is a candidate for larger originals. Standard storage includes 10 GB-months and free allowances for operations. R2 activation goes through checkout and overages can incur charges. Set app quotas before connecting real media. [Supabase pricing](https://supabase.com/pricing) · [R2 pricing](https://developers.cloudflare.com/r2/pricing/) · [R2 setup](https://developers.cloudflare.com/r2/get-started/) |

**Recommended path.** Establish stable item IDs, per-item revisions and a record of what changed. Keep working offline. When devices connect, send only new or changed records and missing originals. Resume interrupted transfers and verify each file. Offer **Keeping up to date**, **Waiting for a device**, or **Review conflicting edits** status that describes the visible outcome. If two devices edit the same note offline, preserve both drafts for review. Once personal pairing works, test managed accounts and private file storage with sample libraries. The same transfer logic can work over Wi-Fi or through a hosted service. Use accounts, per-library permissions, recovery exports, usage limits and backups before a commercial launch. GitHub holds Atlas's code and releases, and device storage or a chosen sync service holds the personal library. Free tiers and pricing were checked on 18 November 2026.

**Check before release.** Pair two devices, edit while both are offline, then reconnect in either order. Verify changes, files, memberships, and restored items. Test a large interrupted transfer and conflict recovery, then check compatibility with Android manual backups.

## 7. Plan readers and canvas as later releases

- **HTML, PDF and EPUB.** Add dedicated built-in readers. Plan text selection, highlights and notes in PDF and EPUB with links back to the exact passage. Evaluate the same experience for safely rendered saved HTML. For EPUB, allow background and text color, theme, font size, spacing and other reading preferences. Save highlights and reading position as Atlas data alongside the original. Use a viewer that keeps imported HTML isolated from the main application. Existing browser preview behavior can remain the starting point during evaluation.
- **Design canvas and developer files.** Give a future visual canvas its own workspace. Plan draggable assets, notes, links, prototypes and editable code blocks. Later, add browsing or referencing local codebases and prototype previews. Store layout separately from the assets so the same file can appear in more than one project. Keep previews and any future code execution isolated. The graph remains a relationship explorer, and the canvas would be a place to arrange project material.

## Proposed order for approval

1. **Reliability.** Autosave, selection, shortcut coverage, the nested search issue, color/type correctness, Markdown peeks and video posters.
2. **Compact workspace.** Home and filters, folder-first browsing and deletion, panels, inspector, menu groupings, and in-place detail zoom.
3. **Connected writing.** Shared picker, slash placement and live Markdown, multi-attach and pasted images, graph responsiveness and tabs. Add split panes once tabs work.
4. **Automation and personal sync.** Local AI writing and reviewable file management with generic MCP access. Pilot device pairing using the revision foundation from the first stage. Hosted provider and hosted sync evaluations follow the personal flows.
5. **Future readers and canvas.** Built-in documents and annotations, then the larger design and code workspace.

Defaults to confirm with the plan are folder-first browsing with descendant contents off, a hidden Home inspector with folder summaries where relevant, and review-first AI with opt-in automatic tagging and filing. The supplied screenshots cover the target interaction and visual density. A further recording would only help if a specific gesture, transition or menu action needs clarification after review.
