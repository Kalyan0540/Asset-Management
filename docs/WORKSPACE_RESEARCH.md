# Atlas workspace research

18 November 2026. The source material was the user's twenty screenshots, the earlier Eagle recording, the existing Atlas implementation, and the products' published help. The observations below describe the examples. The Atlas decisions apply those patterns to a distinct interface. The design canvas remains a later research topic.

## Eagle for library browsing

| Evidence | Atlas decision |
|---|---|
| Screenshot 01 shows a subfolder strip above asset contents, with a control for including descendant files. Eagle documents the descendant toggle when viewing a project root. | Show immediate child folders ahead of assets, including empty children. Start with direct contents and include descendant files once each when enabled. [Eagle subfolder contents](https://en.eagle.cool/support/article/show-subfolder-contents) |
| Screenshots 02 and 03 show tree lines and a contextual folder menu. The recording shows the context menu on assets, rather than a dedicated button on each image. | Retain the compact folder tree. Put each folder's create, rename and expand action in the context menu and keep it accessible using the keyboard. Keep the magnifier and a checkbox on gallery tiles. [Eagle organization help](https://en.eagle.cool/support/desktop) |
| Eagle lists distinct search tools for type, tags, color, rating and shape. Screenshots 07–12 show a hex value on swatch hover, a swatch action menu, selection lists for type/folder/tag, and a color picker with direct text entry. | Integrate a checkbox-based type selector into search. Use the actual file types and allow include or exclude. Normalize hex input and choose a similarity tolerance. Tag/folder selection lists and richer swatch actions are follow-on work. [Eagle search help](https://en.eagle.cool/support/desktop/search) |
| Screenshot 04 shows the media filling the center with the surrounding panes retained. Eagle describes Fit to Window and zoom shortcuts in its file viewing guide. Screenshots 05 and 06 show an inspector and a grouped Export action. | Open images in the center and keep the side panels. Use keyboard navigation, compact zoom controls and a fit action. The inspector continues to hold metadata with autosave. A grouped export menu and richer inspector color actions are subsequent changes. [Eagle file viewer guide](https://en.eagle.cool/blog/post/how-to-preview-files-in-eagle) · [Eagle focus zoom](https://en.eagle.cool/support/article/focus-zooming) |
| The recording shows images and videos being inspected on hover and opened through other commands. Eagle exposes hover preview and spacebar behavior separately. | Preserve hover-to-seek. Cache a representative frame for the tile. Render a Markdown excerpt when a note's magnifier has hover or keyboard focus. Keep Space for a quick preview. [Eagle browse help](https://en.eagle.cool/support/desktop/browse) · [Eagle preferences](https://en.eagle.cool/support/desktop/preferences) |

## Obsidian for links, graph and tabs

| Evidence | Atlas decision |
|---|---|
| Obsidian describes library-wide and local graphs, a text search, toggles for tags, attachments and orphans, display and force settings, and connected-node highlighting. Screenshot 20 demonstrates the small controls panel on the graph canvas. | Provide local and full graph views on the same canvas. Add item search, asset and orphan toggles, neighbor highlighting and Fit. Use the existing typed relations and Markdown embeds as links. The current pass covers one hop in local view. [Obsidian Graph view](https://obsidian.md/help/plugins/graph) |
| Obsidian's Live Preview hides formatting markup away from the active text, while source and reading views remain available. | Preserve readable Markdown as the stored format. Test cursor-aware rendering in the planned editor pass before replacing the current Write and Read controls. [Obsidian views and editing mode](https://obsidian.md/help/edit-and-read) |
| Obsidian tabs can split into horizontal or vertical groups. A note can have a linked view for the local graph, backlinks, or outline. | First preserve independent state per tab. Later consider a split with a note beside a related graph, sharing edits to any item open in both panes. [Obsidian tabs](https://obsidian.md/help/tabs) |

The previous Atlas graph recreated its canvas on changes and used only the first 250 items. The new component gives Cytoscape.js one canvas per mounted view, updates the nodes and edges in a batch, and draws neighboring connections on hover and selection. It starts with a force-directed layout for smaller graphs and a circle for larger ones. This retains Atlas's existing MIT-licensed renderer and avoids adding a second graph dependency before measuring. Sigma.js with Graphology is the alternative for GPU rendering and layout work if larger-library benchmarks call for it. Large collection responsiveness and renderer crossover have yet to be measured. [Cytoscape performance documentation](https://js.cytoscape.org/) · [Sigma.js](https://www.sigmajs.org/) · [Graphology](https://graphology.github.io/)

## Notion for editing and item selection

| Evidence | Atlas decision |
|---|---|
| Notion's `/` command inserts headings, lists, links, images, and other blocks. `/link` and the block's plus button lead to the page selector. Inline links can also be created by searching after `@` or `[[`. | The editor pass will use one searchable picker for slash and plus entry, keep it beside the caret, and add date and type sorting, hover previews and multi-selection. Typed relationships and displayed inline embeds can share the picker while retaining distinct meanings. [Notion shortcuts](https://www.notion.com/help/keyboard-shortcuts) · [Notion links and backlinks](https://www.notion.com/help/create-links-and-backlinks) |
| Notion documents dropping images into a page and inserting files and media through an upload or a link. | Add a paste or drop flow that first saves an Atlas asset, then inserts a stable reference in the note. Use the user's tag routing rules to choose folder membership. [Notion images, files and media](https://www.notion.com/help/images-files-and-media) |
| Notion stores filter and sort configuration with individual database views. It documents keyboard range selection and Delete in the editing context. | Keep keyboard and mouse shortcuts contextual. Keep library layout and filter state separate from the items so a later Atlas tab can restore the user's view. [Notion views, filters and sorts](https://www.notion.com/help/views-filters-and-sorts) · [Notion shortcuts](https://www.notion.com/help/keyboard-shortcuts) |

## Scope of this implementation pass

Autosave and recoverable drafts address the risk of lost edits. The library first gets folder-first navigation, simpler type filtering, selection shortcuts, Markdown peeks, video posters and the center image view. The new graph removes the arbitrary 250-item limit and tests the local/full interaction. See the saved review plan for later editor features, folder deletion and its undo model, advanced inspector and native menu refinements, AI writing and automation, and device sync. The twenty inline screenshot originals remain in the conversation. The associated workspace planning folder holds the original feedback text, approved plan, detailed index and available earlier recording frames.
